# 新剧本制作指南（夜半推理馆）

以《人吃人》为范本，写给以后做第二本、第三本的人（包括以后的 Claude）。
**每次改了引擎、AI、界面，或者踩了新坑，都要回来更新这份文件**：先改「设计规则」或「踩过的坑」，再在末尾的「更新记录」里写一行。

相关文件：`RULES.md`（工程守则、测试命令）、`10_renchiren.js` + `11_renchiren_more.js`（范本数据）、`check.js`（数据检查）、`test/balance.js`（平衡模拟）。

## 1. 一本剧本由什么组成

| 部分 | 放在哪 | 说明 |
|---|---|---|
| 原文 | `text/<前缀>_*.txt` | 背景、每个人物剧本、真相解析。构建时注入为 `TEXT[文件名]`。原文可以直接复用（用户确认过没有版权问题）。 |
| 剧本数据 | `1N_<sid>.js`（可拆两个文件） | `SCRIPTS.<sid> = {…}`，下面第 3 节逐项说明。引擎、AI、界面都只读这份数据。 |
| 美术 | `40_art.js` 里写 `drawPlan<Xxx>(c, round)`、`drawImg<Xxx>(c, key)`，文件末尾挂 `SCRIPTS.<sid>.art = { plan, img }` | 第一轮现场平面图、线索图片（死亡讯息、地图之类）。全部程序绘制，不引用外部图片。 |
| 选本卡片 | `30_ui.js` 的开局设置（`UI.pickSc`）、`50_net.js` 的 `NET.start`、`loadSave(sid)` | 目前还写死 `renchiren`，第二本上线时要改成按 `U.setup.sid`（见第 8 节）。 |

引擎（`20_engine.js`）、Claude 接入（`25_ai.js`）、界面（`30_ui.js`）**不应该再出现某本剧本的人名、线索 id 或时间**。发现写死的，挪进数据。

## 2. 制作流程（按顺序做）

1. **选本**：0.5–2 小时、4–6 个嫌疑人、只有凶手说谎的本最合适（引擎的核心规则）。变格/时间轮回本要先想清楚怎么在“公开/未公开”的模型里表达。
2. **整理真相时间线**：每个人每个时间点在哪、做了什么（`timeline.rows`）。这是一切的基准，后面每条证词都要能落在这张表上。
3. **拆线索**：第一轮现场线索（全公开、要有平面图位置）+ 第二轮每人 2–4 条私有线索 + 1 条现场深入线索。每条线索要回答：它指向谁（`sus`）、它能逼出谁的实话（`show.*.brk`）、它和什么组合成推论（`links`）。
4. **写证词**（`facts`）：每个人“公开了就成立”的说法，带时间的写 `t`。凶手的谎话也是证词（`f_wang_lie`），要能和别的证词/线索撞出矛盾（`contra`）。
5. **写推论**（`facts` 里 `d_` 开头，`who: 'deduce'`）：真相需要几步推理，就拆几条推论。**每条关键推论至少两条得出路径**：AI 在讨论里说出（`talk` 带 `reveal`）、玩家「指出关联」（`links`）。
6. **AI 回答表**（`ans`）：每个嫌疑人 × 每个话题（含 `about_<别人>`）都要有回答，按条件从上到下取第一条能用的。无辜者只能 `truth`/`evade`/`crack`，凶手可以 `lie`。
7. **出示反应**（`show`）：每个嫌疑人被出示关键线索时说什么、透露什么、破防哪个话题（`brk`）。`_` 是默认回应。
8. **AI 讨论脚本**（`talk`）：AI 按顺序挑第一条能说的。第一轮几条开场观察和互问；第二轮按线索公开情况推进推理、出示、追问；最后是凶手反驳（`diff: 'rebut'`）和嫁祸（`diff: 'frame'`）。
9. **真人台词**（`deck`、`finals`、`intros`）：真人扮演嫌疑人时能选的说法。凶手的 deck 要有“原文推荐的谎话”“嫁祸”“等于认罪的实话”“回避”。
10. **答卷和结局**（`questions`、`sides`、`endings`、`epilogues`）。第一题必须是指认凶手（`killer: 1` + `roles`）。
11. **Claude 数据**（`voice`、`dodge`、`secrets`、`confess`、`topicScope`、`topicWords`）。
12. **美术**：平面图、线索图片、`spots`（第一轮热点位置）、`planCaption`、`planAreas`。
13. `node check.js` → 0 错误；`node test/balance.js` → 达到第 5 节的目标；`test/solo.js`、`test/regress.js`、`test/ai.js` 全过。
14. **真人视角试玩**：按第 7 节清单，电脑和手机各走一遍完整局，再用真实 API 跑一局侦探、一局无辜者、一局凶手。

## 3. 数据字段参考

条件函数 `when(P)` 里能用：`P.has(...ids)` 全部已公开、`P.any(...ids)`、`P.round`（1/2）、`P.brk(角色, 话题)` 已破防、`P.human(角色)` 是真人、`P.cut(id)` 推论被反驳了、`P.who` 说话人。

### 基本信息
| 字段 | 说明 |
|---|---|
| `id`、`title`、`sub`、`minutes`、`players`、`blurb` | 选本卡片上的文字 |
| `victim`、`victimId` | 死者名字；死者在证词/时间线里的 id（默认 `zhao`，印章取死者姓的第一个字） |
| `killer`、`suspects` | 凶手 id、嫌疑人 id 列表（座位顺序，也是第一题选项顺序） |
| `bg`、`truth` | 背景、真相原文的 `TEXT` 键 |
| `roles.<id>` | `name`、`seal`（印章字）、`title`、`color`、`book`（人物剧本原文键）、`intro`（AI 默认自我介绍）、`side`（支线描述）、`alias`（别称，自由提问时认人用，如 `['村长']`） |
| `rules` | 玩法说明里的条目 |

### 线索、证词、推论
| 字段 | 说明 |
|---|---|
| `clues.<id>` | `r`（1 第一轮现场 / 2 第二轮）、`owner`（第二轮属于谁）、`scene: true`（第二轮现场深入调查）、`title`、`text`、`img`（线索图片键，交给 `art.img`） |
| `spots.<线索id>` | 第一轮热点在平面图上的位置 `[x, y]`（0–1）。热点之间不要重叠（`regress.js` 会查） |
| `planCaption` | 平面图下的一句说明 |
| `planAreas` | `[x0, y0, x1, y1, 线索id 或 null, 提示]`：平面图上画了、但不是热点的东西，点了要有反应（打开就近线索，或提示“第二轮可以深入调查”） |
| `facts.<id>` | `who`（角色 / `deduce` / 死者 id）、`t`（时间 `HH:MM`，进时间线板）、`text`（以“某某：”开头） |
| `sus.<id>` | 公开后 AI 对各嫌疑人的怀疑加减。凶手相关的推论权重要大 |
| `contra[]` | `{ a, b, who, add, by, say }`：a、b 都公开 = `who` 说谎被抓，`by` 里的 AI 当场指出（说 `say`），怀疑 +`add` |
| `links[]` | `{ a, b, reveal, brk }`：玩家「指出关联」把 a、b 放一起 → 公开推论 / 让某人在某话题破防。错误组合扣评级 |

### AI 的话
| 字段 | 说明 |
|---|---|
| `topics[]` | `{ id, q, when }`：可以问的话题。`about_<嫌疑人>` 自动存在 |
| `topicScope.<话题>` | 话题的范围说明（给 Claude 归类自由提问用）。每个话题都要写，写清楚“问的是什么”，别让“谁有枪”这种问题被硬套进来 |
| `topicWords.<话题>` | 正则：Claude 失败时本地兜底归类用。更具体的话题放前面（`saw` 在 `where` 前） |
| `pressTopics` | 剧本台词说完后，AI 追问真人的话题顺序（默认：所有不带条件的话题） |
| `voteOrder` | AI 平票时的顺序（默认凶手最后，平票不会冤枉成凶手被投） |
| `ans.<角色>.<话题>[]` | `{ when, kind, say, reveal }`，从上往下取第一条满足条件的。`kind`：`truth` / `evade` / `lie`（只有凶手）/ `crack`（慌了但嘴硬） |
| `show.<角色>.<线索>` | `{ when, say, reveal, brk }`。`say: '……'` + `brk` = 沉默后改口。`_` 是默认回应数组 |
| `showTopic.<线索>` | AI 向真人出示这条线索时，真人从哪个话题的 deck 里选回答 |
| `talk[]` | `{ id, r, who, when, say / ask{to,topic} / show{to,id}, reveal, cut, uncut, push, diff, self }`。`who` 可以是数组（第一个不是真人的说）。`diff: 'rebut'` 标准/困难才有（凶手反驳推论，`cut` 把推论打到 ×0.6；无辜者回击 `uncut`），`diff: 'frame'` 只有困难（嫁祸，`push` 加别人怀疑） |
| `idle.<角色>` | 闲话（“听大家说”没新内容时） |
| `dodge.<角色>` | 中性的回避句：剧本外的自由提问、Claude 失败时用。**不能含任何事实或暗示**（以前用 idle，结果胡调研回答“要是能找到我儿子……”，泄露了秘密） |

### 真人的话
| 字段 | 说明 |
|---|---|
| `deck.<角色>.<话题>[]` | `{ kind, say, reveal, push, vol, tip, confess, when }`。`vol: 1` 可以主动发言；`tip` 显示在选项后（“原文推荐的说法”“嫁祸张村民”）；`confess: 1` 等于认罪。无辜者的 `lie` 会被自动过滤 |
| `intros.<角色>` | 正好 3 条：`low` 低调 / `strong` 强势（AI 多一分戒心）/ `mislead` 带点误导（可带 `push`）。侦探 `det` 也要 3 条 |
| `finals.<角色>` | 投票前最后一句 |
| `quick` | 联机快捷语 |

### 收尾
| 字段 | 说明 |
|---|---|
| `questions[]` | `{ q, opts, a, killer, roles }`。第一题指认（`killer: 1`，`roles[a] === killer`）。其余题的选项**每局自动打乱**，写数据时正确答案放哪都行 |
| `sides.<角色>` | `(G, role) => bool`：真人嫌疑人的支线是否完成（+10） |
| `timeline` | `cols`（含死者 id）、`rows`（`[时间, 每列一格]`），复盘逐格播放 |
| `endings` | `killer`（抓对，键名用凶手 id，如 `wang`）、`other`（抓错，`{name}` 替换）、`none`（平票悬案） |
| `epilogues[]` | `{ role, text: G => … }` 每人的后来 |

### Claude 用的数据
| 字段 | 说明 |
|---|---|
| `voice.<角色>` | 说话风格一两句。口头禅写“偶尔用”，否则 Claude 每句都用 |
| `secrets[]` | `{ words, ok }`：这些词在 `ok` 里任何一条公开之前，Claude 不许说出口（原句里有、玩家自己问到的除外） |
| `confess` | 正则：凶手认罪的说法。Claude 改写凶手台词时命中就作废 |

`check.js` 会检查上面大部分引用和必填项；新加字段时顺手给 `check.js` 加检查。

## 4. 设计规则（硬性）

**推理与公平**
- 只有凶手说谎；无辜者只隐瞒、回避。回避本身是线索（AI 记 `evade`）。
- 每条关键推论至少两条得出路径（AI 讨论说出 + 玩家指出关联），否则玩家卡住就无解。
- 凶手的每句谎话都要有一个能撞破它的证据组合（`contra`），并且证据在正常流程里拿得到。
- 时间线板只显示**已公开证词里出现的时间点**。固定列出所有时间点 = 剧透“这个时间有事发生”。
- 答卷选项打乱（以前 8 题里 6 题答案都在第一个）。嫌疑人不能指认自己。
- 第二轮行动点不够查完所有线索（6 点对 13 条），选择本身是玩法；AI 也在同时搜。

**节奏与反馈**
- 讨论一开场就有一个 AI 先说话，不冷场（`enterPhase` 里 `aiStep`）。
- 每个可点的东西都要有反馈：热点之外的家具也给提示（`planAreas`），搜到的线索立刻弹出并可以公开。
- 扣分的操作（提示）先确认。不可逆的操作（结束讨论）要点两次。
- 结局按玩家立场说输赢（凶手没被投出去就是赢；平票是“悬案”）。
- 复盘列出错过的线索、没得出的推论、到最后都没说实话的人。

**AI（脚本）**
- AI 投票只看已公开证据（`sus` + 矛盾 + 回避），平票凶手排最后。
- 真人还有问题没答时，AI 不追问他。
- AI 剧本台词说完后，按 `pressTopics` 追问真人没被问过的话题；再没有就“大家在等你”。

**Claude（见第 6 节）**
- 引擎决定一切事实，Claude 只换说法、只把玩家的话归到已有动作。

## 5. 平衡目标（`node test/balance.js`）

模拟四种局：消极凶手（真人凶手只回避）、聪明凶手（用尽撒谎/嫁祸/反驳）、无辜者×2。看 AI 的嫌疑分。

| 局面 | 目标 | 《人吃人》标准难度 |
|---|---|---|
| 消极凶手 | 被投出，领先 ≥ 4 | 王 13 vs 5.5 ✓ |
| 聪明凶手 | 能脱身，但不是轻松脱身（嫁祸对象领先 2–5） | 张 10.1 vs 王 6 ✓（偏宽松） |
| 无辜真人 | AI 能投中凶手，领先 ≥ 2 | 胡调研局 6 vs 5.5 ✗ 偏险；李警察局 10.1 vs 2.4 ✓ |
| 平票率 | 接近 0 | 0/40 ✓ |

调平衡的旋钮：`DIFF` 里的发言预算 / 行动点 / 提示扣分；`sus` 权重；`contra.add`；`push`；反驳的削弱系数（AI ×0.6、真人 ×0.4）。改完重跑，三档难度都看。

## 6. Claude 扮演 AI 玩家（`25_ai.js` + `shared/aikit`）

**架构**：只有单机/房主调用 Claude；朋友不需要密钥，台词随状态同步。密钥只存浏览器 `localStorage['hub.ai']`，绝不进存档、网络消息、仓库。claude.ai artifact 版用 `sample` 能力（要 `declare_capabilities {sample:{}}`）。

**硬性规则（代码保证）**
1. 引擎先决定事实（谁说什么、透露什么、破防），再让 Claude 改写那一句；日志 `text0` 留着脚本原句。
2. Claude 只拿到：人物设定、**这句之前**已公开的信息（`g.pubAt`）、最近对话、原句。拿不到未公开线索、别人的剧本、真相。
3. 每句过 `aiCheck`：秘密词、时间点必须在原句或已公开证词里出现过、凶手不认罪、不出戏、长度；提问必须还是原来的问题、带问号；剧本外问题的回答不许承认/否认事实。不过就用原句。
4. 玩家自由打字只会被归成已有动作：问某人某话题 / 出示某线索 / 选剧本允许的某句说法 / 剧本外问题（对方用 `dodge` 风格回一句不含事实的话）。不是凶手的玩家说了和自己剧本矛盾的话，直接拒绝并把原话填回输入框。
5. 失败、超时（12/20 秒）、401/429 → 脚本台词；密钥无效时关掉 Claude。

**写新剧本时要准备的**：`voice`、`dodge`、`secrets`（把每个“答案词”都列进去，`ok` 写能合法揭开它的线索/推论）、`confess`、`topicScope`、`topicWords`、`roles.*.alias`。

**踩过的坑**
- Sonnet/Opus 5.5 **不支持强制 `tool_choice`**（400），AIKit 对它们用 auto + 要求 + 文字 JSON 兜底；只有 Haiku 能强制。修之前均衡/高质量档的关键台词全部悄悄退回脚本。
- 引擎先公开、Claude 后改写 → 问话的 AI 会提前引用对方答案里才公开的事。用 `pubAt` 截断。
- Claude 改写提问会换成别的问题（“村子哪不对劲”→“你看到了什么”）。提示词 + 问号检查。
- 话题归类：Haiku 会把“你们村里谁有枪”塞进“村子哪里不对劲”。给每个话题写 `topicScope`，并明确“问别的具体东西一律 topic=none”。18 句测试 Haiku 16/18、Sonnet 16/18 但慢 2.5 倍，归类继续用 Haiku。
- 选中了某人就默认问他；问“你们/大家”要有人回答；句尾没问号也算问题。
- 剧本外问题以前回 `idle` 闲话（“……”、或带秘密的句子），现在按问题本身回一句不含事实的话。
- 玩家自己问出的秘密词，Claude 复述不算泄露。
- 费用：均衡档每局约 50 次调用、$0.03–0.05；自由提问 2–4 秒出结果。

**测试**：`node test/ai.js`（假 API，不花钱）；真实 API 的全流程脚本放会话临时目录，密钥只从环境变量读。

## 9. 踩过的坑（全部）

**引擎 / 规则**
- 删掉不成立的矛盾（“没出门”和“矿泉水”根本不冲突）——每条 `contra` 都要自己读一遍是否真的矛盾。
- AI 在真人没回答时继续追问 → 真人有待答问题时跳过追问他的台词。
- 同一个问题反复问会整段重复 → 第二次只说第一句并标“不耐烦”。
- 闲话刷屏 → 一轮最多一次闲话。
- 朋友掉线后私有线索锁死 → 掉线时公开他的私有线索，AI 接手。
- 凶手总是被抓 / 总是脱身 → 交错 AI 搜证、加反驳/嫁祸、调发言预算；见第 5 节。

**界面**
- 翻看记录时被拽回底部 → 只在本来就在底部时跟随，否则显示「↓ N 条新消息」。
- 旧消息每次重渲染都重新淡入 → 记 `seenI`。
- 弹窗刷新时滚动归零、输入框被清空 → 保留滚动位置；有输入框聚焦时不刷新弹窗。
- 手机上热点标签重叠 → 窄屏只显示编号 + 图例。
- 新手引导盖住输入框 → 有输入框时上移。
- 弹窗里每点一下都闪一下（「指出关联」点线索看起来像“闪一下就消失”）→ 同一个弹窗刷新时原地换内容，不重放淡入动画；「指出关联」每条显示内容摘要，选中的两条在上面完整展开（带图）。
- **弹窗规则**（`30_ui.js`）：`UI.modal(k)` 新开；`UI.modal(k, 1)` 原地刷新并保留滚动；`UI.modal(k, 2)` 原地刷新并回到顶部（切标签用，以前切到新标签停在半中间）。单独的线索卡 `showClue` 也算弹窗（`U.modalOpen = 'clue'`）。
- **自动弹窗不能抢**：AI 问你时自动弹出的问题、打字被拒后重开的回答框，只在 `modalBusy()` 为假时弹——有任何弹窗开着（包括线索卡）或者正在底部输入框打字都等一等。以前正在看的线索卡会被问题弹窗挤掉（“闪一下就消失”），打字到一半会被抢焦点。
- **列表里只有标题 = 看不到内容**：凡是让玩家挑线索的地方（出示、指出关联）都显示内容摘要；记录里“出示了/公开了”的摘要可以点开看全文；第二轮已搜到/已公开的卡片可以再点开。
- 联机朋友搜证：本地还没有房主的新状态，搜到的卡片弹不出来 → 记 `U.pendSearch`，状态回来再弹。
- 第二轮的💡提示按钮绕过了扣分确认 → 所有提示入口统一走 `UI.hint()`。
- 固定的时间线行、正确答案总在第一个、嫌疑人能投自己（见第 4 节）。

**存档 / 多局**
- 真相页的存档以前不算“继续上次”，看真相时一刷新结果就没了 → 真相页也能继续（联机局的真相页按单机打开，不重开房间）。
- 刷新时还有句子在等 Claude 改写（`v: 'p'`），刷新后没密钥就一直显示“…” → 继续时调用 `aiAfter()`：有 Claude 就接着改写，没有就用脚本原句。
- 第二局要把本机界面状态全清掉（`30_ui.js` 里 `G.gid !== U.gid` 那一行）：答卷、关联选择、选中的人、提示确认、待弹的搜证卡片……新加 `U.*` 字段时记得加进去。
- 第一轮讨论没回答的问题会在第二轮讨论开场弹出来 → 进入第二轮搜证时清空 `prompts`。
- 凶手不能指认自己之后，他的指认题永远算错、评级封顶 B → 凶手的指认题按“有没有逃脱”算。

**联机**
- 计时用各自的时钟 → 按房主时钟校正。
- 房主自己离开被当成朋友掉线 → `NET.leaving`。
- 朋友掉线检测不到 → 心跳 4 秒、15 秒超时。
- 朋友主动离开后又自动重连 → close 事件要看 `NET.leaving`。
- 联机存档单机继续卡死 → 二选一：重开同一房间等朋友，或单机继续由 AI 接手。

- 测试直接调 `UI.start()` 时 TitleKit 遮罩挡住点击 → 测试里 `TK.hide()`（真实流程会自动隐藏）。

# 逐章审查与优化：20 点

用户要求：给每一章提出 20 点优化建议，并全部实现。每章由一个作者负责，只改自己的章节文件和通关步骤。

## 范围

只改这三个文件：
- `src/chapters/NN_<id>.js`
- `src/tests/sol/<id>.py`
- `src/reviews/<id>.md`（新建，审查记录）

引擎（`src/js/*`）、`shell.html`、`build.py`、别的章节、别的游戏文件夹都不改，不做任何 git 操作。真的需要引擎改动时，写进 review 的「需要引擎支持」一节，由主会话统一处理；章节里先用现有 API 做到最好。

## 第一步：亲自玩一遍，再写 20 点

1. 通读章节源码和 `src/AUTHORING.md`（尤其 §5 的新 API 和 §7 已知坑），再读第一季里已经优化过的章节作参考：`nighttales/src/chapters/01_mary.js`、`07_hitchhiker.js`、`02_kuchisake.js`（它们用了 `S.vote`、`faces` 惊吓大头像、`endings` 结局收集、密码盘别名等新写法）。
2. 跑一遍 `play.py --shots`，把截图拼成总览图逐张看；危险段（追逐、限时、潜行）要用实时脚本按真人速度模拟一次，确认难度合理、能赢也能输。
3. 写 `src/reviews/<id>.md`：恰好 20 条，每条一行标题 + 一两句说明「现在的问题 → 怎么改」，按类别分组。每条都要具体到这一章（地点、台词、谜题、实体），不写空话。

建议从这些方向找问题（不必每类都有，但 20 条要覆盖至少 6 类）：
- **故事与传说**：传说要素是否完整、版本差异是否呈现、与真实来历是否准确；笔记与档案（legend）是否有错漏；台词是否口语自然、有画面感。
- **谜题**：线索是否公平、可推理；卡关时有没有逐级提示；答案是否容易被瞎蒙；双人分工是否成立。
- **节奏**：开场是否太慢、对话是否太长、跑腿是否重复；15–25 分钟的体量是否合适。
- **恐怖与氛围**：惊吓时机、`faces` 惊吓大头像（本章主要的鬼至少一张）、光照与黑暗度、环境声、`S.tone` 合成的关键音效。
- **危险段**：追逐速度、计时长度、死亡频率、检查点位置、死后重来的状态复位、坏结局是否保留检查点。
- **双人**：关键抉择改用 `S.vote`（并写出两人意见不一致的分支）；需要「一人看笔记一人操作」的地方是否成立；`S.moving/S.running` 判定是否对客机准确。
- **结局**：好/坏结局写进 `endings` 并给 `S.end` 加 `id`；结局文字是否收束；有没有值得加的第三结局或隐藏细节。
- **画面**：地图布局（门、通道、家具遮挡）、精灵辨识度、选章卡片图标、文字溢出、iPad 竖屏是否可读。
- **可玩性与 bug**：真人走不到的地方、调查不到的实体（`solid` 问题）、重复触发的剧情、目标提示 `S.goal` 是否始终清楚、读档后状态错乱。

## 第二步：全部实现

- 20 条全部实现；确实做不了的写明原因并换一条能做的，保证最终 review 里有 20 条「已实现」。
- 不删掉原有的传说要素和关键剧情；改结构时保持章节 id、n、文件名不变。
- 遵守 AUTHORING 的写作要求（不写真实当事人姓名、血腥靠暗示、中文口语）。

## 第三步：验证

在仓库根目录：
```bash
python3 <game>/src/build.py --out <game>/.tmp_<id>/index.html --only <id>
python3 <game>/src/tests/play.py <id> --page <game>/.tmp_<id>/index.html --shots <scratchpad>/shots_<id>
```
- 必须 `<id> OK`，没有 ERRORS，没有 REACH WARNINGS（NPC 正在走路造成的暂时阻挡除外，要在 review 里说明）。
- 用 SOL 变体（放 scratchpad，不进仓库）验证每个坏结局、每种死亡和重来。
- 截图拼图再看一遍，确认改动生效、没有新的布局问题。
- 机器只有 2 核、多人并行：同一时间只开一个 Chromium，跑完立刻结束；不要用 `pkill -f`（会杀掉自己的 shell）；分段写文件、及时落盘。
- 完成后删除 `<game>/.tmp_<id>/` 和 `tests/**/__pycache__`。

## 第四步：汇报

最终回复（简短）：20 条的标题清单（每条一行，标「已实现」）、测试结果、需要引擎支持的事项（如果有）。review 文件末尾也附上测试结果。

# 完美世界 · 石昊篇（文字版）· 开发守则

源码在 `src/`，`python3 build.py --deploy` 生成 `../index.html`。存档键 `wanmeiol.save2`（前缀 `wanmeiol.`），联机房间前缀 `wmol-`。

| # | 规则 | 来源 | 怎么保证 |
|---|------|------|----------|
| 1 | **玩家就是石昊（小不点）。** 剧情按原著的顺序走（石村 → 出村 → 补天阁 → 百断山），人名、地名、凶兽、宝术、宠物用原著的；剧情文字全部原创，不抄原著段落。原著里没交代清楚的地方宁可写得含糊，也不要编造“原著设定”。 | 「我希望是带入石昊的视角」 | 人工 |
| 2 | **没有其他玩家。** 不做世界频道、模拟玩家、交易行、公会、排行榜。热闹靠 NPC：`45_npc.js` 的 `CHATTER` 每条都标了地点和剧情区间，只说当前已经开放的地图和已经发生的事。新加 NPC 台词必须带 `at`、`from`、`to`（夜里才说的加 `night: 1`）。 | 「不需要其他玩家的世界频道，可以加上一些 NPC 的对话，而且对话最好符合目前已经开了的地图」 | `build.py` 检查每条台词的地点、剧情步骤、人名都存在，`from` 不晚于 `to`，不对就报错 |
| 3 | **一次只显示一种画面，三种画面一眼分得清。** 探索（暗绿：地名画、描述、刚发生的几件事、主线、按钮）· 对话（米黄纸：印章名牌 + 台词 + ▼继续/选项）· 战斗（暗红：敌人在上、本回合经过、我方、宝术栏）。完整文字记录、回忆录、凶兽图鉴都收在顶栏「📜 记录」里；底栏只有 探索 · 石昊 · 宠物 · 背包 · 地图；顶栏只有 记录 / 联机 / 设置。新功能先想能不能放进这些页里，不要加新的顶栏按钮和弹窗。 | 「现在页面内容过多」「界面有点过于繁琐，不同类型的界面也分不太清楚」→ 选了“场景切换式” | `node test/mobile.js` 看图 |
| 3b | **不画原著角色的样子。** 说话的人用原创的印章名牌（名字 + 阵营底色：石村朱红、补天阁靛青、清风青绿、外人墨绿、敌人紫），不做头像。 | 版权：原著角色就算画得不完全一样也不画 | 人工 |
| 4a | **选择要有后果。** 剧情选项写进 `C.story.f`，之后一定要在某处读到它（台词、奖励、事件）。不要只存不用。 | 建议 1 | `node test/flow.js` 打印 flags |
| 4 | **灵兽伙伴、宝术、功法都跟着原著剧情得到**（界面里一律叫“灵兽伙伴/灵兽”，不叫宠物；毛球、大红、二秃子；青鳞鹰、狻猊、雷道、打神石、锈剑、小塔；迎霞锻体、骨文、药鼎洗礼、搬血极境、洞天、太一真水、不老泉……）。 | 用户选择 | `node test/flow.js` 最后打印的 pets / sk / gf |
| 5 | 剧情能从头打到尾。 | — | `node test/flow.js` |
| 6 | **联机 = 共享画面 + 交换操作。** 房主跑游戏，加入的人看到同一个画面；谁点“我来操作”谁控制。要让新按钮在联机时能用，把它调用的函数名加进 `60_net.js` 的 `CMD_NAMES`。 | 「联机只实现共享视角，可以切换控制」 | `node test/peerserver.js` 开着，再 `node test/coop.js` |
| 7 | 手机竖屏/横屏、iPad、电脑每个界面都放得下，没有横向滚动。 | IPHONE.md | `node test/mobile.js` |
| 8 | 不经用户确认不改平衡数值（`BAL`、`HERO`、怪物倍率）。 | 用户要求 | 改前先问 |
| 4b | **战斗里石昊和灵兽伙伴各有自己的回合。** 每回合先给石昊选招，再给伙伴选招（伙伴可以防御；“‹ 重选石昊”能反悔），然后按身法依次出手；顶部显示出手顺序。自动战斗时两个都交给 AI。换伙伴、一拳解决、逃跑时不用再给伙伴选。 | 「主角和伙伴都有自己的回合」 | `node test/features.js` |
| 4c | **动画只是回放。** 战斗引擎一次算完一回合，把发生的事记进 `B.ev`（每条都挂在它那行战报上）；`51_anim.js` 按行回放。新战斗效果要同时写进 `fxe(...)` 才会有动画。动画默认开着（就算系统开了“减弱动态效果”也开着——用户要的），能在设置里关掉（`SET.motion`）；测试用 `__dbg.instant` 跳过。 | 「加一些动画，比如对战动画，切换动画」 | `node test/features.js`、`node test/coop.js` |
| 8b | 剧情步骤在存档里按 id（`story.qid`）记。往 `MAIN` 里插新步骤没问题，旧存档按 `OLD_V2` 的顺序换算；不要删改已有步骤的 id。 | 补天阁插入了新剧情 | `fixSave` |
| 9 | 顶层函数不能重名（后面的会悄悄覆盖前面的，第一版就因为两个 `S_cliff` 把剧情弄断了）。 | 踩过的坑 | `build.py` 发现重名直接报错 |

测试：`node test/features.js`（伙伴回合、打断、配合、一拳解决、换伙伴、宝骨、觉醒、兑换、悬赏、探索度、称号、传送、睡到天黑、洞天重开、困难秘境、雷池深处、石毅、难度）· `node test/flow.js`（整条剧情 + 故事后的事件、虚神界奖励、存档码往返）· `node test/coop.js`（共享画面、交换操作、骨文小游戏由队友点）· `node test/mobile.js`（7 种屏幕截图，检查横向溢出）· `node test/hub.js`。

经过用户同意的数值改动（2026-11，建议 6、9、10、14）：`BAL.expMul`（10 层起每层 +6% 经验）、`BAL.storyExp`（剧情战双倍经验）、`BAL.phaseAtk`（首领半血 +25% 攻击）、`BAL.weakMul`（打中弱点 ×1.5，蒲魔树怕火 ×1.6）、`PROF`（宝术用 30 次小成 +10%，100 次大成 +20%）、宠物技能倍率（毛球输出 / 大红群攻 / 二秃子控制治疗）。

第二批（2026-11，20 条可玩性 + 动画，用户“可以都做”）：狈祖附体 +35% → +25%（不和首领半血狂怒叠得太狠；风狈其余数值不变，自动战斗学会防御大招后 7 层胜率约 80%）；难度 简单（敌人气血 ×0.75、攻击 ×0.8）/ 标准 / 困难（×1.25、×1.15，经验 ×1.15）；宝术配合：骨文锁链后下一次物理伤害 ×1.3、锈剑砍流血 ×1.35、雷道劈晕眩 ×1.25、狻猊打狂怒 ×1.2；一拳解决：敌人全部比你低 4 层以上且不是首领/剧情/秘境；灵兽觉醒（亲近 100）全属性 +15% 并多一招；宝骨效果见 `12_extra.js` 的 `RELICS`；悬赏奖励：宝药、灵药、30% 升级经验、熟练度 +5；探索完成：宝药、灵药、30% 升级经验；困难秘境：敌人等级 max(秘境+5, 你+1)，奖励宝药×3、灵药×3、60% 升级经验，首通送一件没有的宝骨。

第三批（2026-11，用户提出：伙伴技能配合、敌人变强但格子变多、补状态、背包分类与买卖、吃药不占回合）：
- 伙伴招式分 攻击 / 增益（给石昊）/ 减益（给敌人）/ 防守 四类，亲近 25 / 50 / 75 解锁更多。配合：破甲（防御 -35%）、印记（石昊打它 +30%）、战吼（石昊攻击 +25%）、加持（下一击必暴）、嘲讽（敌人打伙伴）；石昊把敌人打晕，伙伴打它 ×1.3。伙伴 AI 见 `petPick`。
- 敌人随等级变强：`BAL.foeHp/foeAtk`，11 层以前不变，18 层达到 气血 ×1.6 / 攻击 ×1.25。同时 宝术栏 4 → 5（10 层）→ 6（14）→ 7（18），宝骨栏 2 → 3（12）→ 4（17）。用 `node test/balance.js` 看自动战斗对主要首领的胜率和剩余气血，改数值前后都跑一次。
- 战斗里吃药不占回合，每回合限一次。城镇都能休息；野外「歇脚」每到一处一次，回 40%，25% 会被打断。灵石：打怪、悬赏、探索完成会给；城镇能卖（半价），村中货郎、补天阁山门外门坊市能买（价格见 `PRICE`）。
- 出手顺序：按身法排，但石昊和伙伴连着出手（排在两人里较早的位置），先后由玩家在伙伴回合里选（`C.duo`，默认石昊先）。见 `turnOrder`。
- 招式栏：石昊带 `barSlots` 门宝术，栏满时再选会换下最低阶的；伙伴带 4 招（觉醒后 5），新学会的招自动替换同类里最低阶的，在灵兽页可以手动换。见 `petBar` / `togglePetMove`。
- 画面切换不许闪：三个画面常驻、用透明度交叉淡化；离开对话时等 140ms（下一句往往马上就来），见 `applyMode`；同一个人连着说话不再盖章。只有进入战斗有整屏转场。
- 伙伴成长：伙伴有自己的等级（`petLv`，打仗拿经验，上场的拿全额、没上场的 30%，比石昊低时 ×1.6），每比石昊高 1 级属性 +3%（低则 -3%，同级与旧版一样强）；第一卷结束前最多比石昊高 2 级，之后能练到 30 级。招式升阶（`RANK_COST`）每阶 +20%，3 阶持续多一回合。觉醒（亲近 100）+15%，返祖（已觉醒、25 级）再 +15%。
- **不用现实时钟。** 游戏内时间：每天 `BAL.dayLen` 格（探索 1、走一步 ¼、歇脚 1、通关秘境 2），到 `BAL.duskAt` 天黑，熬满一天自动天亮；在城镇“一觉睡到天亮”就是新的一天（`newDay`）。虚神界次数/每日奖励、悬赏都按游戏天（`gameDay()`）刷新；凶兽首领每天一头，打掉或换天为止。新功能不要用 `today()` / `Date` 来计时。
- **非战斗的互动用小游戏，不要用打一架凑。** `44_mini.js`：举石锁（看准时机）、引雷（收缩圈）、破阵（全部按灭）、潜行（趁它睡熟迈步）、搬石（连点）。都能跳过，剧情里跳过 = 照常往下走、没有加成；失败也要有一句交代，不卡剧情。联机时只在房主那边算，`miniTap` 在 `CMD_NAMES` 里，动的部分按 `t0` 画（发给队友时换算成队友的时钟）。
- **敌人要会说话。** `46_talk.js` 的 `SAY`：开场 / 残血 / 倒下各一两句；野兽不说人话，写它的动作（放在（）里）；石昊偶尔回嘴。台词在战斗里冒气泡，记进战报。
- **江湖传闻**（`RUMORS`）：地点画上方偶尔飘一句别人的话，不占版面，也记进📜记录。只能讲已经发生的事（别人眼里的你）或给下一段剧情埋引子，都带 `from`/`to`，`build.py` 会检查。 电脑/平板（`body.cols`）常驻最近 3 条，手机一次飘一条；点它打开「📜 记录 → 江湖传闻」，按天列出全部听过的传闻（`C.rumorLog`，最多 80 条，只由主机写入，队友看同步来的）。

## 通用：以后做剧情游戏要保持的东西（用户在这一版里逐条提出或认可的）
1. 一次只显示一种画面（探索 / 对话 / 战斗），颜色一眼分得清；完整记录收进按钮里。画面切换用交叉淡化，对话句与句之间不许闪；同一个人连着说话不重复盖章。
2. 说话的人用原创的印章名牌，不画原著角色。
3. 选择要有后果；有回忆录能重读剧情；剧情步骤按 id 存档，插新剧情不坏旧档。
4. 战斗：敌人意图提前显示，大招能防御也能打断；主角和伙伴各有回合、可选先后、技能分开播动画并配合；吃药不占回合；自动战斗会吃药、防大招、打弱点；有难度选项；能“一拳解决”弱怪。
5. 动画默认开（不跟随系统“减弱动态效果”），设置里能关；动画只是回放引擎记录（`fxe`），关掉动画也要能看到伤害和状态（卡片上的本回合伤害）。
6. 成长线不能到顶：宝术熟练度、宝骨、伙伴等级/升阶/觉醒、格子随境界增加；敌人随之变强，用 `test/balance.js` 量胜率和剩余气血再定数值，数值改动要先给用户看旧值 → 新值。
7. 不用现实时钟：游戏内的天和昼夜，睡觉换天，每日内容按游戏天刷新。
8. 支线、悬赏和主线并列在任务列表里，能选追踪；城镇能休息、野外能歇脚；背包分栏、能买卖。
9. 非战斗互动做成可跳过的小游戏；敌人有台词；有不占位置的江湖传闻，且不超出剧情进度；宽屏常驻最近几条，点开能看全部历史（存进存档）。
10. 氛围跟着地点走：区域配色用 CSS 变量（由 `ATMO` 设置），探索/战斗背后画地点、加飘动粒子和淡纹理；新区域要在 `ATMO` 里配一套。粒子受“动画”开关控制。
11. 地点画（`52_art.js`）用山水笔法：`crest` 分形山脊 + `washHill` 墨色渐变和皴笔、`mistBand` 雾带、`pine`/`fir`/`leafTree`/`cottage`/`hall`/`spire` 等笔刷、`grain` 纸纹；不要用简单几何形直接拼，每处一个标志物，避免堆满。
12. 小游戏失败不自动结束：问「再试一次 / 跳过」（`miniRetry` / `miniGiveUp`，骨文 `runeRetry` / `runeAccept`），跳过时剧情走失败那一支，绝不卡关。
14. 高潮演出（`47_epic.js`）：每个小章节的高潮战传 `epic`（name/sub/seal/intro/phase/low/end），关键剧情用 `cine()`（回忆用 `mem`），章节开头 `chapterCard()`；`low` 写成某个人说过的话，要能戳到人；战斗气泡按字数停留。
15. 对话：`48_banter.js`（战斗插话，每回合最多两句）、`49_talks.js`（💬 闲聊，带选项，每段一次）、`CHATTER`（路过听到的话）。每个人的口头禅要一致，笑点要从角色里长出来。
16. 传闻和闲话的 `from` 写事件发生**之后**的那一步（当前步骤 = 还没发生）；传闻一个存档只听一次（`C.rumorLog`），build 查重复。
17. 每条都要有自动测试（`features.js` 逐项检查），联机测试（`coop.js`）、整条剧情（`flow.js`）、屏幕（`mobile.js`）每次都跑。
18. 点了没反应就是 bug：按钮要么生效、要么提示原因；跳章/读档遇到进行中的剧情或战斗直接放弃它（`dropRunning`），并保留玩家设置。
19. 新地点的入口不能藏在还锁着的地点后面；`flow.js` 必须用真实寻路一直走到最新一卷的结尾。
20. 新卷完成清单见 OPTIMIZATIONS.md 第 37 条（剧情、地点、敌人台词、epic、闲话传闻闲聊、野外事件、悬赏交换、跳章、境界、配色和画、音乐、平衡、flow）。
21. 跳章把教学提示标成已看过；战斗气泡没有空位时选重叠最少的位置；单行长代码里的注释只用 `/* */`。
22. 一个 NPC 在多处出现时，找人用 `npcLocNow`（先找现在去得了的）；角色在剧情里死去或离开后，从 NPC 列表和传闻说话人里移除。
23. 剧情步骤 id 唯一（build.py 检查）；补新卷前先回头查原著，看前面有没有漏掉的大事。
24. 往后写新卷前先核对前面几卷的时间线，发现顺序错了就回头重排，并同步挪动闲话/传闻的时间范围；对一直成立的台词，有效期写到 `q_fin`。
25. 地图出口必须双向（build.py 检查）。
26. 后期首领机制写在 `MOBS[id].mech`，处理都在 `31_mech.js`；新机制必须在日志里写明怎么破，并在 features.js 里加一条确定的测试。
27. “打不赢”的剧情战一律用 `holdOut`（撑住 N 回合），结果只影响旗标和多出来的台词，不能卡住剧情。
28. 城镇/无怪地点的支线和事件用 `EVENTS`（到达触发），野外的用 `WILD`；支线写进 `SIDEQ`（带 `loc`），任务列表能追踪。
29. 新的玩家选择要有旗标，并考虑进 `recapText`（卷末回顾）和 `finaleEchoes`（结局）。
30. 轮回（第二世）保留的字段只在 `NG_KEEP` 里改；新存档字段默认值要在旧存档里也能用（`|| 0`）。
31. 和进度有关的文字（人物介绍、提示）写成函数，不在加载时读 `C`；有怪的地点必须写 `lv`（build.py 检查）。
32. 提交前跑 `test/sweep.js 0 10` 和 `test/sweep.js 10 99`：每个跳章起点走遍地点、探索、翻遍页面，不许有报错或 undefined/NaN。
33. 新系统、新伙伴、新的剧情选择，都要在跳章里跟上（`JUMPS` 的旗标、`jumpLate` 的伙伴/悟道/天庭）；features.js 的 `jumpLate` 检查最后一档。
34. 伙伴的出战人数、特性、推荐都在 `33_party.js`；新伙伴要写 `PET_TRAIT`（特性 + 适合的仗）和 `partyAdvice` 里的推荐条件，并用 `PARTY=1 PET=<id> node test/balance.js` 单独测。
